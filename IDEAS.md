# Ideas

Running list. Newest at top. Mark done with `[x]` and a short note; leave open as `[ ]`.

- [ ] **Academic-source channel (scholarly papers)** — add a source that reads real literature, not just web/GitHub/YouTube. Port the no-key APIs documented by the `paper-lookup` skill (K-Dense-AI/scientific-agent-skills, MIT, stdlib-only scripts): PubMed, PMC + Europe PMC (full text), bioRxiv/medRxiv, arXiv, OpenAlex, Crossref, Semantic Scholar, CORE, Unpaywall. No credentials required (optional keys only raise rate limits). Wire it as a discovery+fetch source: topic → academic search → abstracts / open-access full text into the notebook. **Not a skill drop-in** — Notebook is a deterministic pipeline, so vendor/adapt the scripts as a channel, don't run the SKILL.md. Its key gotcha (shared with our fetch layer): *these APIs fail with HTTP 200* — verify response shape, not status. Own phase; sized after the fetch-backend work (obscura seam) lands.

- [ ] **fetch.py ordered backend seam (urllib → obscura)** — generic web pages currently have one urllib path; a challenge/JS wall (Cloudflare, PyPI "Client Challenge") loses the source. Add an ordered, real-probed backend chain (Agent-Reach pattern): urllib first, then `obscura fetch <url> --dump text --stealth` (local Rust headless browser, V8 — proven to clear the PyPI wall where urllib + curl_cffi both failed). Escalate on failure OR blocked-shape (`_looks_blocked`: challenge markers / thin content), not just HTTP status. `FETCH_BACKEND` pins one. Record which backend served each source (`fetched_via`). Installer probes obscura + yt-dlp as soft deps (absent ≠ abort; urllib still serves easy pages). curl_cffi evaluated and dropped — obscura dominates it (runs the challenge JS; curl_cffi can't).

- [x] **Read a YouTube URL as its transcript** — shipped. A research topic naming a YouTube video now reads the actual transcript via yt-dlp (local, no API key, no OAuth), not nothing. `agents/fetch.py`: `is_youtube()` host match; `_fetch_youtube_sync()` = two yt-dlp calls (subs judged by files written since a per-language 429 sets a nonzero exit even when subs land; best-effort title via `--print`); `_vtt_to_text()` strips timestamps/tags and dedupes roll-up caption lines. Routes youtube → github → generic-web in `fetch_one`. English (`en.*,en`), auto or manual subs. Verified live (Agent-Reach review video → title + transcript) + 4 offline mocked tests (78 pass). Evaluated `youtube-subscriptions-ingest` (OAuth + YouTube Data API, metadata-only, entity wikilinks) and rejected it — breaks the no-key rule and yt-dlp transcripts are strictly more content.

- [x] **Read real sources instead of paraphrasing search snippets** — shipped (`d491bfb`, `01d6aea`). Was: `research(topic)` fed the whole topic string to DDG and summarized the snippets, so a topic naming a URL never read it (it hallucinated an unrelated answer). Now `agents/fetch.py` fetches URLs named in the topic (GitHub API metadata + README + file tree; else stripped page text), the primary doc drives follow-up queries, DDG is demoted to link **discovery** only, and every discovered link is fetched and read. `agents/researcher.py` gathers facts source-by-source; `agents/notebook.py` writes an incremental interlinked note-set (`index.md` + one `sources/<slug>.md` per source + `summary.md`, cross-linked with `[[wikilinks]]`) that Obsidian graphs on its own. **Fact-gathering, not conclusions:** the summarizer gathers pros AND cons with a neutral takeaway; the evaluator gates on grounding + coverage, not on reaching a verdict. Subsumes "Query refinement before search" below.

- [x] **Native Ollama endpoint for real context** — shipped. Switched the ollama path from the OpenAI-compat `/v1` client to native `/api/chat`: only native honors `options.num_ctx` (compat silently clamps to the model's 4096 default and truncates documents — verified). `num_ctx` is content-sized per call (bucketed `_ollama_num_ctx`) with grow-on-overflow retry, not a fixed huge window (which reloads a giant KV cache and taxes the CPU); `OLLAMA_NUM_CTX` pins a fixed value. `OLLAMA_TIMEOUT` (default 1800s) covers slow CPU generation — 600s was below one call. Reasoning maps to native `think` (`none`→off, `low`/`medium`/`high` kept — ornith honors levels). Ported the blank→thinking fallback for the finish=length blank-content case. Supersedes port-plan step 4 (`reasoning_effort` via compat) below.

- [x] **Package as `Notebook` — interactive CLI + installer** — shipped on `development`. Interactive-only flow (`cli.py`): Ollama preflight, ask topic, readline-edit, suggest+edit output dir name, collision handling (reuse/new/abort), confirm. `dir_name`/`name` threaded through `run_pipeline` → `write_outputs` → `hook_obsidian` so the chosen name drives both the output dir and the vault note. Root installer (`install.sh`) → `/opt/Notebook` + `/usr/local/bin/Notebook` symlink, dedicated venv, generated `.env`; checks Obsidian + Ollama + model; discovers vault home and offers a dedicated `Notebook` vault or an existing one; reinstall preserves `.env`. `uninstall.sh` leaves user data. Full `/opt` run not yet executed (needs sudo). Plan + verification checklist: `NOTEBOOK_PLAN.md`.

- [ ] **Support local models via Ollama** — run the pipeline against a local model instead of the Anthropic API. Ollama exposes an OpenAI-compatible endpoint at `http://localhost:11434/v1`, so this means a configurable base URL + model name (env-driven) plus a client abstraction.

  **Model decision:** `ornith-1.5:9b` (9B dense, qwen35 core, 262k ctx, tools + thinking). Ornith is purpose-tuned for agentic + coding tasks, which matches this pipeline; provenance is public (Ornith research group, on HuggingFace + Ollama library). Baseline/control: `qwen3.5:latest` (neutral base). Quality escalation: `ornith-1.5:35B` (MoE) if 9B summarizer JSON is unreliable.

  **Port plan:**
  1. [x] **Client abstraction** — `agents/llm.py` `complete()` dispatches on `MODEL_PROVIDER` (`anthropic`|`ollama`). Ollama uses `openai.AsyncOpenAI` at `OLLAMA_BASE_URL`. Env: `MODEL` (falls back to `CLAUDE_MODEL`). Clients are lazy singletons (no key needed at import).
  2. [x] **Message/response shape** — `anthropic_text()` (joins `type=="text"` blocks) vs `openai_text()` (`choices[0].message.content`), both behind `complete()`.
  3. [x] **web_search** — done via DuckDuckGo (`ddgs`), no key. `agents/search.py` does the search; researcher feeds results to `complete()` and compiles sourced bullet notes. Unified path for both providers (dropped the Anthropic server-side web_search). Live: researcher now returns real 2026 findings with URLs.
  4. [x] **thinking output** — thinking models spend the token budget on reasoning and return empty `content` (finish_reason=length). `think:false` via extra_body is IGNORED by the compat endpoint; `reasoning_effort="none"` works. Wired as `ollama_extra()` (env `OLLAMA_REASONING_EFFORT`, default `none`). `parse_json` still backstops any leak.
  5. [x] **System prompt** — summarizer and evaluator pass their own `system` (strict JSON / one-word verdict), overriding ornith's baked-in prompt.
  6. [x] **Verify** — offline suite covers pure helpers (`tests/test_llm.py`) and mocked per-provider `complete()` (`tests/test_llm_complete.py`: text extraction, arg passing, system prepend, reasoning_effort, tools-ignored, unknown-provider). Live smoke on `ornith-1.5:9b` passes end-to-end. 41 tests total.

- [x] **Auto-hook output into Obsidian** — done. `summary.md` now carries YAML frontmatter (topic, date, verdict, tags). When `OBSIDIAN_VAULT` is set, each run symlinks it into `<vault>/Research/<slug>.md` (`hook_obsidian` in `agents/output.py`) and drops an `unhook.sh` into the result dir, hardcoded to that link and safe (removes only if it's a symlink). No-clobber: a real file at the target is left untouched. Env: `OBSIDIAN_VAULT`. **Updated by the source-reading redesign (see top):** output is now a folder of interlinked notes (`index.md` + `sources/*.md` + `summary.md`, cross-linked with `[[wikilinks]]`), and the WHOLE folder is symlinked into `<vault>/Research/<name>` so the links resolve and Obsidian draws the graph. Entity/concept wikilinks (turning tech mentions into nodes) deliberately NOT pursued — the structural cross-links already give the graph.

- [x] **Query refinement before search** — done via the source-reading redesign (see top). The topic is no longer thrown at DDG verbatim: URLs named in the topic are fetched and read first, and the primary document's content generates the follow-up search queries. DDG serves only to discover more source links.

- [ ] **Latency on the CPU-bound 9B** — `ornith-1.5:9b` (6.2GB) spills the 4GB VRAM → runs 69% CPU / 31% GPU at ~2.6 tok/s (known hardware limit). Lowering `max_tokens` does NOT help: agents stop naturally below the cap (research generates ~398 tokens, finish=stop, not the 1500 cap). Real levers measured: tok/s (a model that fits VRAM, e.g. granite4.1:3b = ~35 tok/s, but lower quality — rejected, quality first), fewer generated tokens (terser prompts), and keep-alive (done: avoids ~85s cold reload).

  Per-agent reasoning (quality-over-speed choice): extraction/research=none, summarize=low, evaluate=medium. Measured on `ornith-1.5:9b`, native `/api/chat`, full-document notes: generation ~2–4 tok/s (prefill ~225 tok/s); a full run reads 1 primary + up to 3 discovered sources then summarizes+evaluates, so it is tens of minutes, not seconds. **Blank-content fix:** summarize/evaluate `max_tokens` raised **1200 → 4000** — at 1200 the reasoning pass consumed the whole budget and returned blank (a "low" read_primary produced 1200 thinking tokens / empty content, measured). Reasoning levels are kept (user: quality over speed); a blank still falls back to the model's thinking text. **Watch:** a medium evaluator that loops to REVISE is expensive at this tok/s; the grounding/coverage gate (not a verdict gate) reduces spurious REVISEs.
